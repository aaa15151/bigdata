# 实时数据卡片实施路线

日期：2026-11-24。工作目录：`D:\大数据\movielens-bigdata-dashboard-1-main`。

## 一、范围与完成标准

只新增一个“实时数据”模块入口和一个卡片。已有离线分析、ALS 推荐、实时回放、相似电影、用户画像、电影关系网以及其 API、数据和脚本保持原样。新增入口沿用现有模块切换机制。

卡片展示最近批次评分量、平均评分、活跃用户、低分占比、最近 30 批趋势、推送状态和更新时间。数据明确标记为 MovieLens 历史评分实时回放，不伪称近期真实评分。批次为处理时间统计，区别于旧模块的五分钟事件时间窗口。

默认启动仍展示原结果；实时服务没有启动时，新卡片明确显示未连接，不用随机数或归档快照冒充实时数据。

## 二、独立链路

限速回放 → 独立 Kafka 评分 Topic → Spark Structured Streaming 微批聚合 → HDFS 独立批次 JSON → Kafka 结果通知（携带已提交的小型聚合结果）→ Spring Boot 单消费者 → WebSocket 广播 → 新 ECharts 卡片。

沿用实验四先保存再通知的顺序。为不修改原 Flask API，新服务提供自己的 HTTP 快照接口和 WebSocket；通知携带完整单批聚合，避免浏览器访问 HDFS。服务保存最近 30 批，首次连接发送快照。Kafka 通知 Topic 保留结果，用于服务重启恢复。

建议独立 Topic：`movielens-live-ratings`、`movielens-live-updates`。独立 HDFS：`/movie-live/<run_id>`。每次新演示使用不同 run_id；checkpoint 不与原作业共用。不删除原 Topic、checkpoint 和结果。

## 三、逐步实施

### P0 基线核查
1. 核对模板、模块切换 JS、已有 API 和流任务。
2. 记录 Java/Maven/Python、集群地址及可访问性，不输出凭据。
3. 保存原模板副本，记录已有 API 的基线。
4. 确认新服务端口 8088 可用；浏览器默认访问当前主机 8088，可在卡片配置服务地址。

### P1 新增独立实时服务
新增 `realtime-service` Maven 模块；Kafka consumer 在后台单线程运行，不为每个浏览器创建 consumer。消费结果 Topic，从保留记录恢复最近 30 批；按 run_id + batch_id 去重。广播发送设置超时，关闭连接时清理会话。

接口：`GET /api/live` 返回快照；`WS /ws/live` 首次发送快照、后续发送更新。服务地址默认仅本地使用；允许来源通过配置限定为本地看板地址。服务连接状态与最后数据时间分开显示。

### P2 新增回放和 Spark 作业
新增 `pipeline/live`，不改旧 `pipeline/streaming`。
回放读取 ratings.dat，校验四列，带上 run_id、event_seq、原始时间；限制每秒发送量，默认每秒 100 条，最多 30000 条。Kafka key 采用 run_id；原始数据不改写。
Spark 每 5 秒触发，过滤非法数据，按本批计算记录数、平均分、活跃用户和低分比例。先将单批聚合写入不可变 HDFS 目录，再发送 Kafka 结果消息；重试时复用已提交结果，通知可以重复。不得宣称 HDFS 与 Kafka 跨系统严格一次事务。

### P3 新卡片
只在 index.html 增加一个 tab、对应 section、独立 JS 引用。复用已有 panel、totals 和 ECharts 样式。独立 JS 负责连接、30 批趋势、状态、指数退避重连。收到重复消息不累计；旧请求不得覆盖新数据；隐藏模块切换回来时 resize。

### P4 编译和本地验证
1. Maven 编译服务，校验前端语法和模板渲染。
2. 验证批次去重、最近 30 批上限、快照输出。
3. 运行原快照 API 回归，确认原功能仍可用。
4. 浏览器查看新卡片：无服务显示未连接；有服务无数据显示等待；真实批次到达后更新。
本地协议样例测试只能记为测试，不算真实集群联调。

### P5 集群部署与启动
执行前记录实际 broker、Spark 安装目录、Kafka 客户端库及 HDFS 地址。已有脚本版本只作参考，不擅自升级集群。
1. 检查 HDFS/YARN/Kafka 健康。
2. 创建两个独立 Topic，初次演示单分区即可。
3. 启动新 Spring Boot 服务（环境变量指定 broker）。
4. 启动新 Spark 作业，使用本次独立 HDFS/checkpoint。
5. 正常启动原看板，切换到新增实时数据卡片。
6. 启动限速回放，逐项核对 Kafka offset、Spark 批次、HDFS JSON、通知和浏览器数值。
具体可执行命令随实现写入 `pipeline/live/README.md`，不得将尚未实现的参数当作现有命令。

### P6 验收
使用可人工核对的小样本验证 count/avg/distinct users/low ratio。两个浏览器必须同时收到更新；断开新服务后旧功能正常；重连自动补快照；重复通知不重复计数；重启 Spark 使用原 checkpoint 恢复。暂停回放后标记数据更新时间，不把连接正常等同于数据持续更新。

## 四、回退

停止新增 producer、Spark 作业和 Spring Boot 服务即可停止新链路。还原模板新增入口和脚本引用可隐藏新卡片。保留新增目录便于排查；无需回滚旧 API、模型或数据。不要运行清空原 HDFS 或 Kafka 的命令。
